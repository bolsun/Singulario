# Визуальная спецификация: частица-осколок и атом-предмет-шар

Автор: художник · утверждено пользователем 2026-10-01.
Концепты: https://claude.ai/artifact/AX4jHxC4Z1grNKxXGrct3C (выбран «Осколок»).

## Решение
- **Частица** — осколок: неправильный гранёный камешек, остаток материи схлопнувшейся вселенной.
  Раньше частица была шаром и путалась с центром атома.
- **Атом-предмет** (атом в дырке, T007) — прежний шар частицы, **без выреза центра**. Шар = маленький
  атом: по смыслу совпадает с центром атома, от осколка-частицы отличается формой.
- Читаемость: осколок (углы) — материал; шар (круг) — атом любого размера.

## Что сделать в коде (задача для ведущего программиста)
Сейчас частицы и предметы — один MultiMesh чанка с одной текстурой (`ParticleSpritePath`), предмет
отличается `INSTANCE_CUSTOM.w = 1` (шейдер вырезает центр). До задачи предмет рисуется осколком с
вырезом — временно.
1. Предмет рисуется спрайтом `atom_item_gray_16px.png`, вырез центра для него выключить.
   Дешёвый путь (на усмотрение программиста): текстура-атлас 32×16 (осколок | шар), шейдер палитр
   при `v_item` берёт правую половину — без второго MultiMesh.
2. Эффекты, где предмет показан «кружком цвета тира с тёмной серединой» (`OnItemTaken` у звезды,
   `OnItemAbsorbed` у ЧД), — тот же шар без выреза.
3. Атом-предмет в UI/инвентаре, если где-то рисуется кольцом, — шар.

## Не входит
- Разные варианты осколка и отражение в месторождении — позже, если россыпь будет выглядеть
  однообразно.

## Варианты осколков и глубина (2026-10-01, утверждено пользователем)
Россыпь из одинаковых осколков выглядела однообразно (особенно 4 px — «дождь»). Решение: несколько форм
одного размера, у всех свет сверху слева; отражения и повороты не используем (свет поехал бы).

Полосы вариантов (квадраты n×n подряд слева направо, те же серые уровни):
| Файл | Вариантов | Размер кадра |
|---|---|---|
| `Resources/Textures/particle_variants_gray_16px.png` | 3 | 16×16 (кадр 0 = нынешний `particle_gray_16px`) |
| `Resources/Textures/particle_variants_gray_8px.png` | 3 | 8×8 |
| `Resources/Textures/particle_variants_gray_4px.png` | 3 | 4×4 |
| `Resources/Textures/particle_variants_gray_2px.png` | 1 | 2×2 (точка, новый размер) |
Одиночные `particle_gray_16/8/4px.png` пока остаются (их использует игра); после задачи — убрать.

Что сделать в коде:
1. **Месторождение:** вариант кадра — из хеша частицы (как размер), постоянный. Доли размеров:
   16 px — 10%, 8 px — 25%, 4 px — 40%, 2 px — 25%.
2. **Глубина в месторождении:** ~30% частиц (из хеша) — на тон темнее: индекс палитры −1 тон
   (тон 1 не ниже 1, контур 0 остаётся 0). Одно число на экземпляр в шейдере палитр. В дырках атомов
   яркость обычная (читаемость линии).
3. **Частица в дырке атома тоже в своём варианте** (просьба пользователя) — и не меняет его при
   передаче. Хеш от позиции не годится (вариант менялся бы при переходе к соседу). Предложение: маленькое
   поле варианта (0..2) в `RingSlot`, задаётся при захвате из источника (детерминированно, например хеш
   клетки источника и `GlobalTick`) и копируется проходами A/B, горизонтом и т.п. вместе с частицей. Только
   вид: на законы не влияет, в хеш симуляции (`--sim-selfcheck`) — на усмотрение программиста; в
   сохранении не нужно (содержимое дырок не сохраняется). Атлас частиц чанка: 3 осколка 16 px + шар
   предмета = 64×16.
