# T024 — варианты осколков и глубина (месторождение и дырки атомов)

Модель: Opus · effort: medium
Ветка: `feature/particle-variants` от `experimental`.
Зависимости: после T023 (атлас частиц чанка, флаг `atlas_halves`). Параллельно с задачами, правящими
`NucleusLayer.cs` (передача частиц, буферы отрисовки), `Crossroad.cs`, `DepositLayer`/`DepositLayout`, не запускать.

## Цель
По `Docs/Art/particle-item-spec.md`, раздел «Варианты осколков и глубина» (утверждено пользователем):
россыпь частиц разнообразнее — несколько форм одного размера, точка 2 px, часть частиц месторождения
на тон темнее (глубина). Частица в дырке атома тоже в своём варианте и сохраняет его по всей линии.
**Только вид:** законы симуляции, порядок обхода, сохранения не меняются.

## Текстуры (уже в репозитории, `.import` пока не закоммичены)
Полосы кадров n×n слева направо, серые уровни 0/64/128/191/255 = тоны 0..4 палитры:
| Файл | Кадров | Кадр |
|---|---|---|
| `Resources/Textures/particle_variants_gray_16px.png` | 3 | 16×16 (кадр 0 = прежний `particle_gray_16px`) |
| `Resources/Textures/particle_variants_gray_8px.png` | 3 | 8×8 |
| `Resources/Textures/particle_variants_gray_4px.png` | 3 | 4×4 |
| `Resources/Textures/particle_variants_gray_2px.png` | 1 | 2×2 |

Число кадров брать из ширины картинки (`ширина / высота`), не зашивать «3» в нескольких местах.

## Что сделать

### 1. Месторождение: варианты и размер 2 px
- `DepositLayout.cs`: у `Particle` — `SizeClass` 0..3 (16/8/4/2 px), новое поле `Variant` (кадр) и `Dark`
  (глубина). Доли размеров у ядра: 16 — 10%, 8 — 25%, 4 — 40%, 2 — 25% (`ShareLarge`/`ShareMedium` +
  новая доля для 4 px; остаток — 2 px). Мостики: без 16 px — 8 — 35%, 4 — 40%, 2 — 25%
  (решение ведущего: мостик тоньше ядра, как и сейчас).
- Вариант и `Dark` — **новыми вызовами `U(ref h)` после существующих**, чтобы не сдвинуть уже
  выбранные фазы/периоды/приоритеты (раскладка остального не «прыгает»). Вариант = `(int)(u · кадров
  размера)`, у 2 px всегда 0. `Dark` = `u < DarkShare` (`DarkShare` = 0,3).
- Если доли выведены в `[Export]` на `DepositLayer` — обновить там же и добавить `DarkShare`.
- `DepositLayer.BuildAtlas`: атлас из четырёх полос в один ряд (16 px: x 0..47, 8 px: 48..71,
  4 px: 72..83, 2 px: 84..85; итого 86×16) — смещения полос вычислять из размеров картинок и передать в
  шейдер (uniform `vec4 strip_x0` + `atlas_size`), а не дублировать константами.
- Константы `Sprite16/8/4` → пути к четырём `particle_variants_gray_*`.

### 2. Глубина (только месторождение)
- `deposit_particle.gdshader` (частицы месторождения рисует он, не `nucleus_palette`): все 4 канала
  `INSTANCE_CUSTOM` заняты (тир, размер, фаза, период) → упаковать в `y` одно целое:
  `size + 4·variant + 16·dark` (в шейдере `floor`/`mod` с +0,5 против погрешности float). Описать
  раскладку в шапке шейдера.
- Темнее на тон: `level = round(src.r · 4)`; при `dark` и `level ≥ 2` → `level − 1` (тон 1 не ниже 1,
  контур 0 остаётся 0); `idx = level / 4`. Прозрачность не трогать.
- В дырках атомов глубины нет (читаемость линии) — `nucleus_palette.gdshader` по яркости не меняется.

### 3. Вариант частицы в дырке атома
- `RingSlot` (`NucleusLayer.cs` ~696): поле `Variant` (byte/int 0..2) — **только вид**, комментарий об этом.
  `CrossParticle` (`Crossroad.cs`): такое же поле; `Crossroad.Enter` принимает вариант.
- Где частица рождается:
  - захват из источника (шаг 3 `SimTick`, ~2638): вариант = детерминированный хеш (`srcRow`, `srcCol`,
    `GlobalTick`) mod кадров — целочисленный (SplitMix64, как в `Goals.Rng`/`DepositLayout.Mix`), без
    `Random`, без `float`;
  - случайное заполнение и импорт/шаблоны (~4176, ~5377, ~5438): хеш (клетка, номер слота) — не
    добавлять вызовы `_rng`/`rng`, чтобы не сдвинуть последовательность случайных чисел поля;
  - порт слоя 2 (~2902, заморожен) и прочие — `default` (0), не трогать.
- Где частица переносится — копировать вариант: `TryPeekGive` (перекрёсток → `RingSlot`), `PutReceived`
  (обе ветки), всё, что строит `new RingSlot { … ColorTier = content.ColorTier … }`. Найти все места
  поиском `new RingSlot` и `.Enter(` и проверить каждое. ЧД и звезда частицу поглощают — там ничего не нужно.
- Предмет (`IsItem`) — шар, вариант не используется.
- Сохранение — не нужно (содержимое дырок не сохраняется).
- **Хеш симуляции (решение ведущего):** `Variant` в `StateHash` **не включать**. Хеш = законы; так
  `--sim-selfcheck` с одними параметрами до и после задачи обязан дать **те же хеши**, что и доказывает,
  что законы не тронуты. Комментарий в `StateHash` об этом.

### 4. Атлас частиц чанка (дырки)
- `BuildParticleAtlas` (~1253): 3 кадра из `particle_variants_gray_16px.png` + шар
  `atom_item_gray_16px.png` → 64×16. `ParticleSpritePath` → путь к полосе вариантов (проверить, что
  `Scenes/Main.tscn` его не переопределяет).
- `nucleus_palette.gdshader`: флаг `atlas_halves` заменить на `atlas_frames` (число кадров; 0 —
  прежнее поведение для тел, дырок, точек `_dotMaterial`). `INSTANCE_CUSTOM.w` у частиц чанка — номер
  кадра (0..2 осколок, 3 = кадров−1 — шар предмета); `uv.x = (uv.x + кадр) / atlas_frames`.
  `_particleMaterial` (~1437) — `atlas_frames = 4`.
- Буферы: `PutCustom` для частиц дырки (~4054) и перекрёстка (~4119) — `w` = кадр вместо 0/1.
- Эффекты звезды и ЧД (`OnItemTaken`/`OnItemAbsorbed`) не трогать.

## Не входит
- Отражения и повороты частиц, новые формы, анимация захвата.
- Глубина в дырках атомов, смена варианта при передаче.
- Любые изменения законов, порядка обхода, `Touch`, сохранения.
- Вращатели, бросатели, порты/слой 2 (заморожены) — вариант там `default`.

## Критерии готовности
- `dotnet build Singulario.sln` — без ошибок и новых предупреждений.
- `--sim-selfcheck` (одни и те же `--ticks`, `--modes=fe`, `--plain=N`) **до и после** задачи даёт
  одинаковые хеши; в отчёте — команда и оба результата.
- В игре: месторождение — частицы трёх форм на 16/8/4 px и точки 2 px, примерно треть темнее на тон,
  контур не светлеет и не исчезает; при перестройке (смена стадии) форма у оставшихся частиц не меняется.
- В игре: частицы в дырках разной формы, яркость обычная; одна частица, пройдя линию (в т. ч. через
  перекрёсток), сохраняет форму; предмет — по-прежнему шар.
- Тела атомов, дырки, точки дальнего зума, звёзды — без изменений (общий шейдер палитр с `atlas_frames = 0`).
- Отчёт: что проверено в игре, что только сборкой.

## Риски
- Общий `nucleus_palette.gdshader`: ошибка с `atlas_frames` ломает все спрайты атомов → по умолчанию 0.
- Упаковка в float: `floor(y + 0.5)` и `mod` — без этого на некоторых GPU кадр «соседа».
- Пропущенное место копирования `RingSlot` — частица молча сменит форму (не баг законов, но критерий
  не выполнен). Проверить поиском все конструкторы `RingSlot` с `IsHole = false`.
- Nearest и соседние кадры в атласе: при уменьшении квада проверить края на зуме около `AtomDotZoom`.

## Процесс
`git checkout -b feature/particle-variants experimental` → прогон `--sim-selfcheck` на исходном коде
(записать хеши) → короткий план → подтверждение пользователя → коммиты по шагам со сборкой → отчёт →
слияние в `experimental` в основной папке по правилам `CLAUDE.md`.
