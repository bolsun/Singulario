Модель: Sonnet · effort: medium (вид по готовой спецификации; симуляцию не трогает).

## Контекст в коде (проверено)
- `Scripts/EnergyClusterLayer.cs` — `TileMapLayer`, **по узлу на тир** (`ParticlesSoruces0/1/2` в
  `Scenes/Main.tscn`, `Tier` 0/1/2 = Ж/К/С, совпадает с `CoreTier` 0/1/2). Скопление —
  `ParticleCluster` (`Cells`, `Amount`, `MaxAmount`, `Stage`); стадия — `DepletionStage`
  (0..3 = >75 / 50–75 / 25–50 / <25%), смена — в `ConsumeAt` → `ApplyStageTiles`.
  Соседство скопления — `DiagonalClustering` (сейчас 8 направлений).
- **Ловушка 1:** `CellsVersion` растёт при установке/стирании/исчерпании, но **не при смене стадии**.
  Нужен отдельный счётчик вида (см. шаг 1). `CellsVersion` не менять по смыслу — на нём
  `ChunkComposition` (T015).
- **Ловушка 2:** `NucleusLayer.VisibleChunks` содержит только чанки из `_chunks` (где есть/были
  атомы, T014). Месторождение в чанке без атомов туда не попадает — свечение атомов
  (`GlowLayer.UpdateAtoms` → `TryGetChunkGlowVersion`) его не увидит. Видимость месторождений
  считать самим: по прямоугольнику камеры и своему индексу «чанк → клетки источников».
- `Scripts/GlowLayer.cs` — буфер свечения (T020): пятна `glow_spot.gdshader`, канал тира —
  `TierWeights(tier, strength)` в `INSTANCE_CUSTOM`, корни `_grayRoot`/`_tierRoot`, гашение к
  `NebulaZoom` — `AtomFade(zoom)` / uniform `fade` материала. Сюда добавить пятна облаков.
- Шейдер палитр `Resources/Shaders/nucleus_palette.gdshader` (строка палитры —
  `INSTANCE_CUSTOM.x`, атлас — `NucleusLayer.BuildPaletteAtlas(PalettePaths)`); частицы атомов
  рисуются серым спрайтом `particle_gray_16px.png` через него.
- Время: `NucleusLayer.GlobalTick`, `SubTickFraction` (на паузе стоят). Зум: `AtomDotZoom`,
  `NebulaZoom`. Слой 2: `ViewLayer.IsLayer2`.
- Спрайты `Resources/Textures/particle_gray_8px.png`, `particle_gray_4px.png` — в репо **без `.import`**:
  открыть проект в редакторе Godot один раз, закоммитить сгенерированные `.import`.

## Что сделать
1. **`EnergyClusterLayer`** — минимальные правки, только чтение наружу:
   - `VisualVersion` — растёт при любом изменении `CellsVersion` **и** при смене стадии скопления.
   - `StageAt(row, col)` (стадия скопления клетки) и, для мостиков, «одно скопление ли у двух
     клеток» (`SameClusterAt` или id скопления).
   - Отрисовку старых тайлов можно выключать (`Visible`/`SelfModulate` узла) — для переключателя.
   Логику кластеров, расход и сохранение не менять.
2. **Чистый класс `Scripts/DepositLayout.cs`** (без Godot: без `Vector2`, `GD`, `Mathf`; по образцу
   `ChunkComposition`) — раскладка вида по входу «клетки одного тира + стадия + принадлежность
   скоплению»:
   - детерминированный хеш клетки (целочисленный, напр. SplitMix64 как в `Goals.Rng`) — без `Random`;
   - центр «ядра» клетки (смещение к 4 соседям того же скопления + разброс из хеша);
   - пятно облака: радиус и сила по стадии (таблица спецификации);
   - частицы у ядра (20 на клетку) и мостики (5 на пару 4-соседей одного скопления): угол,
     расстояние, размер (16/8/4 по долям 15/35/50%), фаза, период (кратен 256 тиков), приоритет;
     видимость по порогу стадии отбирается **здесь**, при перестройке, а не в шейдере.
   Числа — в клетках, float допустим (это вид, не симуляция), но результат — чистая функция входа.
   Комментарий в шапке: что считает и почему чистое.
3. **`Scripts/DepositLayer.cs`** (Godot; создаётся из кода, как `CrossroadLayer`/`TerritoryLayer`;
   над тайлами месторождений, под атомами) — частицы:
   - свой индекс «чанк → клетки источников всех трёх тиров», перестройка индекса по
     `VisualVersion` (не каждый кадр); MultiMesh чанка — только если его данные изменились;
   - видимые чанки — по прямоугольнику камеры (ловушка 2); невидимые не обновляются;
   - **один MultiMesh на видимый чанк** с постоянными данными экземпляра (центр ядра или концы
     мостика, угол, расстояние, фаза, период, размер, тир). Свободных 4 float `custom_data` мало —
     включить и `UseColors` (ещё 4 float). Три размера спрайта — один атлас 16+8+4, собранный при
     загрузке (тогда MultiMesh один); пиксели спрайта не растягивать (1 арт-пиксель = 1 пиксель мира);
   - новый шейдер `Resources/Shaders/deposit_particle.gdshader`: движение (покачивание у ядра,
     ход по мостику с изгибом) в `vertex()` от uniform тика (`GlobalTick + SubTickFraction`,
     передаётся раз в кадр на общий материал), позиция округляется до пикселя мира; цвет —
     через атлас палитр тира, как в `nucleus_palette.gdshader` (взять ту же текстуру палитр);
   - CPU каждый кадр не пересчитывает экземпляры — только uniform тика и видимость.
   - Показ: только при зуме ≥ `AtomDotZoom`, не на слое 2.
4. **`GlowLayer`** — пятна облаков: свои MultiMesh на видимый чанк месторождений (индекс и
   видимость — из `DepositLayer` или общего помощника, не дублировать обход), в `_tierRoot`,
   канал тира через `TierWeights`. Перестройка по `VisualVersion`. Гашение — тем же `fade`, что
   у атомов (к `NebulaZoom`), на слое 2 нет. F5 (дизеринг/мягкий) и L работают для облаков сами.
5. **Переключатель старый/новый вид** (отладка, не сохраняется): **F7** (свободна; F8 занята
   редактором) — новый вид (облако + частицы, тайлы скрыты) ↔ старые тайлы (без облака и
   частиц). Старт — новый вид. Надпись режима на 1,5 с, как у F4.
6. **CLAUDE.md** — абзац «Живое месторождение (T022)» в «Текущее состояние кода» (классы, версия
   вида, F7, ловушка видимости), T022 в списке задач. Новые строки интерфейса — ключи в `en.po`.

## Не входит
Механика месторождений (расход, стадии, кластеризация, сохранение); полёт частицы из облака к
атому; рваный край облака; новые анимированные ассеты; туманности T015 (уже учитывают источники).
Замеры и нагрузочные тесты не делать (прототип) — производительность обеспечить устройством кода
(перестройка по версии, MultiMesh на чанк, движение в шейдере).

## Критерии готовности
- [ ] Сборка без ошибок и новых предупреждений; `.import` для 4px/8px закоммичены.
- [ ] Соседние клетки скопления — одно облако цвета тира (пятна срастаются), между ядрами ходят
      частицы по мостикам; цвета Ж/К/С различимы.
- [ ] При расходе запаса облако на смене стадии сжимается и тускнеет, дальние частицы пропадают;
      на <25% — тлеющие ядра; при исчерпании всё исчезает.
- [ ] Месторождение в чанке без атомов тоже светится и анимируется (ловушка 2).
- [ ] Анимация стоит на паузе; на средне-дальнем зуме частиц нет, облако гаснет к `NebulaZoom`;
      на слое 2 ничего не рисуется.
- [ ] Раскладка детерминирована: перезагрузка сохранения даёт тот же рисунок.
- [ ] F7 переключает старый/новый вид; F5 и L действуют на облака.
- [ ] `ChunkComposition`, `--sim-selfcheck` не затронуты (симуляция не менялась — прогнать
      selfcheck один раз коротко, чтобы убедиться).
- [ ] CLAUDE.md обновлён, ветка влита в `experimental`.

## Риски
- Сила/радиус пятен рядом со свечением атомов может пересветить линии — подобрать `[Export]`,
  при сомнении показать художнику скриншот, не менять спецификацию самостоятельно.
- Большие месторождения (сотни клеток в чанке) → тысячи экземпляров частиц на чанк; это нормально
  для MultiMesh, но перестраивать только чанк, где сменилась версия, если индекс это позволяет.
- Стирание клетки не делит скопление (`EraseClusterAt`) — мостик может пересечь дыру; принять как есть.
