# T027 — типы звёзд по размеру (печь Ж 3×3, фабрика К 5×5, сверхгигант С 7×7) и рецепты в JSON

Модель: Opus · effort: high
Ветка: `feature/star-types` от `experimental`.
Зависимости: T026 влита. Задача трогает `SimTick` (подвод к звезде, производство, выдача), формат сохранения и
`StateHash`, поэтому параллельно с ней не запускать задачи, которые правят `StarSet`, `StarLayer`, `GridDraw`
(прогиб), `GlowLayer` (звёзды) и сохранение в `NucleusLayer`.

## Цель
Решение GDD, «Производство → Роли звёзд» (2026-10-01,
https://claude.ai/code/artifact/9cf8f132-726d-4cf1-b623-86551e34a7c4), и визуальная спецификация
`Docs/Art/star-types-visual-spec.md` (коммит 0e3e528 — нечётные размеры):
- У звёзд нет тиров: **цвет = тип = размер**. Цвет атома по-прежнему означает тир.
- **Ж — печь (жёлтый карлик), 3×3** (след как у нынешней звезды). Рецепт не выбирается: печь сама определяет его по входу
  (8 частиц Ж → атом Ж; атом Ж + 8 частиц К → атом К; атом Ж + 8 частиц С → атом С). 256 тиков.
- **К — фабрика (красный гигант), 5×5** — роль нынешней звезды-сборщика. Рецепт выбирает игрок (ЛКМ по звезде):
  звезда Ж, звезда К, звезда С.
- **С — сверхгигант, 7×7.** Ставится и стоит, рецептов нет (заготовка станции комет).
- Планеты не делаем.
- **Рецепты и типы звёзд — в JSON** (решение пользователя): кто производит, ингредиенты и их количество,
  время, ёмкость выходного буфера, размер типа. Правка числа = правка файла, без пересборки.

## Решения ведущего программиста (принять или поправить до старта)
1. **Выход и установка.** Все размеры нечётные (3/5/7; чётные отменены): клетка выхода — средняя клетка стороны,
   как сейчас (`Col + Size / 2` и т. п.); при установке клетка под курсором — центральная клетка следа
   (верхняя левая = курсор − `Size / 2`), как сейчас. Каталог (шаг 1) отклоняет чётный `Size` с ошибкой.
2. **Что берут звёзды и как печь выбирает рецепт** (решение пользователя 2026-10-01).
   - **Печь** берёт частицы и не больше одного атома-основы и делает из них атомы. **Фабрика** частиц не берёт —
     только атомы и объекты (атомы-предметы; звёзды-предметы по линии пока не ездят). Рецептов, которые
     разбирают атом на частицы, нет и быть не может (результат — только атом или звезда).
   - Печь выбирает рецепт **сама и только при пустом буфере**. Рецепт начинает его **стартовый предмет**:
     у рецепта с атомом-основой — только атом-основа; у рецепта без основы — его частица. Значит, частицы Ж
     начинают «атом Ж», атом Ж начинает «атом К»/«атом С», а частицы К и С рецепт не начинают — случайная частица
     не перехватит печь. Кандидаты — рецепты печи, доступные игроку (`IsRecipeAvailable`).
   - Дальше печь **принимает** предмет, только если после него в буфере остаётся хотя бы один кандидат, которому
     хватает всего, что в буфере (буфер ⊆ ингредиенты кандидата). После атома Ж первая частица К закрывает путь
     С, и наоборот. Когда кандидату хватает всего — рецепт уходит в работу; несколько сразу — первый в порядке
     JSON. Пока идёт работа, буфер набирается на следующий рецепт по тем же правилам.
   - **Лишний предмет** печь не берёт: он остаётся в дырке атома перед печью и занимает её (линия теряет 1/8
     пропускной способности). Убрать — ПКМ по атому и поставить его заново. Нового кода для этого не нужно —
     это нынешнее поведение «ненужного рецепту». Позже это решат фильтр или сброс на планету (не в этой задаче).
   - **ЛКМ по печи переключает сторону выхода** (на следующую по часовой, как R). Закрепления рецепта нет.
3. **Старые сохранения и шаблоны (тир → тип).** Число `Tier` у звезды = номер типа (0 Ж, 1 К, 2 С); сохраняется
   **центр** следа (новая верхняя левая = старый центр − `Size / 2`; у Ж 3×3 след не меняется). Звезда, которая в новом размере не помещается (пересечение, закрытая
   территория), пропускается с предупреждением в лог — как сейчас при импорте. Рецепт в старом формате —
   индекс в старой таблице (0 `atom_y`, 1 `atom_r`, 2 `atom_b`, 3 `star_y`) → переводится в Id; если рецепт не
   принадлежит типу звезды (старая звезда К делала атом К) — рецепт по умолчанию для типа. Буфер
   ингредиентов из старого формата не восстанавливается (сгорает; содержимое дырок и так не сохраняется).
   Выходной буфер и `Producing/Elapsed` — восстанавливаются, если рецепт сохранился, иначе работа сгорает.
   Звёзды в инвентаре: тир → тип с тем же номером.
4. **Скорость** не зависит от цвета звезды (GDD): время — у рецепта в JSON (`Ticks`). `StarRecipeTicks` и
   `StarSpeedByTier` из `NucleusLayer` убрать.

## Формат JSON — `Data/recipes.json`
Путь — `[Export] RecipesPath` в `NucleusLayer` (по образцу `GoalsPath`). Пример (числа — стартовые,
составы звёзд К и С — **заглушки до решения геймдизайнера**, см. «Вопросы»):

```json
{
  "StarTypes": [
    { "Type": 0, "Name": "печь",        "Size": 3, "OutputCapacity": 10, "Choice": "Auto"   },
    { "Type": 1, "Name": "фабрика",     "Size": 5, "OutputCapacity": 10, "Choice": "Player" },
    { "Type": 2, "Name": "сверхгигант", "Size": 7, "OutputCapacity": 10, "Choice": "None"   }
  ],
  "Recipes": [
    { "Id": "atom_y", "Name": "атом Ж", "Producer": 0, "Ticks": 256,
      "Result": { "Kind": "Atom", "Tier": 0, "Holes": 8 },
      "Ingredients": [ { "Kind": "Particle", "Id": 0, "Count": 8 } ] },
    { "Id": "atom_r", "Name": "атом К", "Producer": 0, "Ticks": 256,
      "Result": { "Kind": "Atom", "Tier": 1, "Holes": 8 },
      "Ingredients": [ { "Kind": "Atom", "Id": 0, "Count": 1 }, { "Kind": "Particle", "Id": 1, "Count": 8 } ] },
    { "Id": "atom_b", "Name": "атом С", "Producer": 0, "Ticks": 256,
      "Result": { "Kind": "Atom", "Tier": 2, "Holes": 8 },
      "Ingredients": [ { "Kind": "Atom", "Id": 0, "Count": 1 }, { "Kind": "Particle", "Id": 2, "Count": 8 } ] },
    { "Id": "star_y", "Name": "звезда Ж", "Producer": 1, "Ticks": 256,
      "Result": { "Kind": "Star", "Type": 0 },
      "Ingredients": [ { "Kind": "Atom", "Id": 0, "Count": 8 } ] },
    { "Id": "star_r", "Name": "звезда К", "Producer": 1, "Ticks": 256,
      "Result": { "Kind": "Star", "Type": 1 },
      "Ingredients": [ { "Kind": "Atom", "Id": 0, "Count": 4 }, { "Kind": "Atom", "Id": 1, "Count": 4 } ] },
    { "Id": "star_b", "Name": "звезда С", "Producer": 1, "Ticks": 256,
      "Result": { "Kind": "Star", "Type": 2 },
      "Ingredients": [ { "Kind": "Atom", "Id": 0, "Count": 4 }, { "Kind": "Atom", "Id": 1, "Count": 4 }, { "Kind": "Atom", "Id": 2, "Count": 4 } ] }
  ]
}
```
- `Choice`: `Auto` — рецепт выбирает звезда по входу (правило п. 2), `Player` — игрок (ЛКМ перебирает доступные
  рецепты своего типа), `None` — рецептов нет.
- Проверка каталога закрепляет п. 2: у рецептов `Auto` не больше одного ингредиента-атома, и его `Count` = 1;
  у рецептов `Player` нет ингредиентов `Particle`.
- Ингредиент: `Particle` — цвет частицы 0..2; `Atom` — тир атома-предмета 0..2 (серого атома-предмета пока нет).
- Порядок рецептов в файле — приоритет печи, если буфера хватает сразу нескольким (п. 2), и порядок перебора ЛКМ у фабрики.
- `Name` — ключ перевода (русская строка), новые ключи — в `Data/Localization/en.po`.
- Ёмкость **входного** буфера остаётся «на 1 рецепт» (в JSON не выносится).
- Визуальные числа (тело 0,733 стороны, корона ×2, прогиб, `TierSeeds`) в JSON не выносятся — это вид, они
  в коде (таблица по типу, см. шаг 5), но **считаются от `Size`** там, где спецификация задаёт пропорцию.

## Что сделать
1. **Данные без Godot** (`StarSet.cs` или новый `StarRecipes.cs` + `.cs.uid`): `StarType` (Size, OutputCapacity,
   Choice), `StarRecipe` (Id, Name, Producer, Ticks, Result, Ingredients), таблица `StarCatalog` — разбор JSON,
   проверка (уникальные Id, типы и тиры в диапазоне, `Count`/`Ticks`/`Size`/`OutputCapacity` ≥ 1, `Size` нечётный, ≤ 9,
   у `Player`/`Auto` есть рецепты, ограничения п. 2 на атомы и частицы) с понятной ошибкой. Ошибка при старте — в лог, игра идёт со встроенной
   таблицей по умолчанию (она же — образец формата; числа = файл выше). `StarRecipes.All` как статическая
   таблица уходит; `StarYellowAtoms` — тоже.
2. **`Star`**: `Tier` → `Type`; `Size` — свойство (из типа), не `const`. Буфер ингредиентов — счётчики по виду
   предмета (частица 0..2, атом 0..2), а не по индексам рецепта, — так одинаково работают обе схемы выбора.
   Рецепт: у фабрики — выбранный (`RecipeId`), у печи — выбирается по правилу п. 2; в работе —
   `ActiveRecipe` (что звезда делает сейчас; для значка и для `TryFinishToOutput`). `Duration` = `Ticks`
   рецепта. `OutputCapacity` — из типа. `OutputCell`/`RingCells`/`IsRingCell`/`Overlaps`/`ContainsCell` —
   от `Size`, клетка выхода — средняя клетка стороны (`RingCells` даёт `4 × Size` клеток). `StarSet.Add` — пересечение
   по размерам обеих звёзд. Логика выбора рецепта печи (п. 2) — здесь, в `Star`, не в `NucleusLayer`.
3. **`NucleusLayer`**: загрузка `RecipesPath` при старте (как задания); `FeedStarsFromNeighbors` спрашивает у
   звезды «примешь ли этот предмет» (метод `Star`, учитывает доступность рецептов); `TickStars` и
   `OutputStarsToHoles` — длительность и ёмкость от рецепта/типа; `IsRecipeAvailable` — по Id;
   `StateHash` — добавить тип, буфер-счётчики и `ActiveRecipe` (детерминизм).
   `RemoveTarget` (T026) — сторона следа из `star.Size` (0,3 с / 0,5 с / 0,7 с — правило T026 уже общее).
   Всё, где сейчас `Star.Size` / `star.Tier`, — по типу (список: `grep -n "Star.Size\|\.Tier" Scripts/StarLayer.cs
   Scripts/GridDraw.cs Scripts/GlowLayer.cs Scripts/NucleusLayer.cs`).
4. **Сохранение** (`SavedStar`): `Type`, `RecipeId` (строка), буфер-счётчики, `ActiveRecipe`; загрузка старого
   формата — п. 4. Шаблоны: `Data/Templates/reward_star_y.json` — перевести на новый формат (печь Ж,
   `Type 0`), остальные шаблоны звёзд не содержат. Экспорт шаблона (B) пишет новый формат.
5. **Вид (`StarLayer`)** по спецификации: таблица по типу вместо `BodyDiameterCells` (тело 2,2 / 3,7 / 5,1 клетки ≈ 0,733 × `Size`,
   корона × `CoronaScale`), `StarWarp` в `GridDraw` — по типу (0,12 / 0,16 / 0,2), пятно звезды в `GlowLayer` —
   центр следа, масштаб по стороне. Рампа и seed — по номеру типа (`TierTones` по-прежнему тоны Ж/К/С).
   Превью установки, рамка выхода, шеврон, дуга — от `Size` и клетки выхода. Печь: значок — результат
   `ActiveRecipe` во время работы, в простое значка нет. С (`Choice: None`): всегда «простаивает»
   (`StateOf`), без значка, дуги, шеврона, рамки выхода; R над ним ничего не делает.
6. **Инструмент**: кнопки ★Ж/★К/★С — типы; ЛКМ по печи — следующая сторона выхода (как R), по фабрике —
   следующий доступный рецепт своего типа, по С — ничего. `DefaultRecipe` — первый доступный рецепт своего типа. Настоящий режим:
   установка тратит звезду этого типа из инвентаря, снятие возвращает (как сейчас по тиру).
7. **Перезагрузка рецептов без перезапуска (отладка)**: клавиша `F9` (проверить, что свободна в игре и
   не перехвачена редактором; иначе — свободная рядом, записать в CLAUDE.md) — перечитать `RecipesPath`.
   Ошибка — старая таблица остаётся, сообщение в лог и короткая надпись в HUD (как у F4). Успех — у всех
   звёзд сгорают буфер ингредиентов и работа в процессе; рецепт фабрики ищется по Id, пропал — по
   умолчанию для типа; выходной буфер остаётся (обрезается до новой ёмкости — лишнее пропадает). Если
   поменялся `Size` типа — звёзды этого типа, которые не помещаются, удаляются с сообщением в лог
   (возврат в инвентарь в настоящем режиме). Это отладочное действие: детерминизм от него не требуется.
8. **Задания** (`Data/goals.json`): Id рецептов прежние (`atom_y`, `atom_r`, `atom_b`, `star_y`), цепочку не
   менять — её перестройку под «Порядок с ролями звёзд» делает геймдизайнер отдельно. Проверка
   неизвестного рецепта в наградах (`NucleusLayer` ~481) — по новому каталогу.
9. **CLAUDE.md** — раздел звезды (T006/T008/T011/T017): типы, `Data/recipes.json`, правило печи, F9; убрать `StarRecipeTicks`/`StarSpeedByTier` и «тир звезды».

## Что не входит
- Планеты, станция комет, любая работа сверхгиганта С.
- Перестройка цепочки заданий и наград (геймдизайнер, отдельно).
- Новые цвета и правки шейдера звезды (спецификация: шейдер не меняется).
- Ёмкость входного буфера в JSON, рецепты серого атома, ускорение звёзд технологиями.
- Замороженное: приём атомов от вращателя/бросателя (`TryFeedArrivedToStar`, флаг выключен) — только чтобы
  компилировалось, груз, слой 2.

## Критерии готовности
- `dotnet build Singulario.sln` — без ошибок и новых предупреждений.
- `--sim-selfcheck` (короткий, по умолчанию) — хеши полного обхода и работы по событиям совпадают на поле со
  звёздами всех трёх типов.
- В игре (песочница): ставятся печь 3×3, фабрика 5×5, С 7×7, центр следа под курсором; превью и отказ — своего
  размера; ПКМ с удержанием 0,3 / 0,5 / 0,7 с.
- Печь: линия частиц Ж → атомы Ж; атом Ж + частицы К → атом К; частица К или С при пустом буфере печь не
  занимает и остаётся в дырке перед ней; второй атом Ж печь не берёт; значок — текущая работа; ЛКМ — сторона выхода.
- Фабрика не берёт частицы ни в каком рецепте. Выход — средняя клетка стороны у всех размеров, R крутит его по часовой.
- Фабрика: ЛКМ перебирает звезда Ж/К/С (только доступные), звезда-предмет копится в буфере, Ctrl/Shift+клик —
  в инвентарь.
- С: стоит «спящим», ничего не принимает и не отдаёт.
- Правка `Data/recipes.json` (например, `Ticks` атома Ж 256 → 64, `OutputCapacity` 10 → 3) + F9 — новое число
  видно в игре без перезапуска; файл с ошибкой — сообщение, игра работает со старыми рецептами.
- Старое сохранение (автосохранение до задачи) загружается: звёзды Ж стали печами на том же месте, К — фабриками
  5×5, С — сверхгигантами 7×7 (центр на месте) или пропущены с предупреждением; `reward_star_y.json` ставит печь.
- Прогиб сетки и свечение у всех трёх размеров — по центру следа.

## Риски
- Лишняя частица в дырке перед печью отнимает 1/8 линии, пока игрок не переставит атом (решение пользователя;
  фильтр/сброс — позже). Если атом Ж в буфере, а К и С не приходят, печь стоит — это ошибка схемы игрока.
- 5×5 и 7×7 закрывают много клеток: в старых сохранениях звёзды К и С, вокруг которых тесно, пропадут
  (предупреждение в логе). Ж (3×3) след не меняет.
- Буфер-счётчики меняют `StateHash` — сверять selfcheck только внутри одной сборки (как всегда).
- `Size` перестаёт быть константой: пропущенное место с `3` в виде даст смещённую рамку/прогиб — проверять
  все три размера глазами.

## Вопросы геймдизайнеру (не блокируют: в JSON стоят заглушки)
- Составы звезды К и звезды С (сейчас 4 Ж + 4 К; 4 Ж + 4 К + 4 С) и время производства звёзд.

(незакоммиченные изменения, не `experimental` или конфликт — стоп и вопрос пользователю).
