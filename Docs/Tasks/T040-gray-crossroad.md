# T040 — перекрёсток только у серого, не вплотную; шеврон выхода цветом соседа

Модель: Sonnet · effort: medium
Ветка: прямо в `experimental` (правка ввода, `PlaceDecision`, загрузки и вида; законы передачи не меняются).
Зависимости: T039 влита. **Шаг 5 (шеврон) — после правки художником `Docs/Art/crossroad-visual-spec.md`**
(цвет шеврона «сосед не цветной»); шаги 1–4 от неё не зависят. Не запускать параллельно с задачами, правящими
`PlaceDecision.cs`, `CrossroadLayer.cs`, `NucleusLayer` (ввод ЛКМ, `TryPlaceNucleus`, `ApplyFieldData`, `Crossroads()`).

## Цель
GDD, «Перекрёсток» (решено 2026-10-02): перекрёсток — стык, а не дорога. Режим перекрёстка есть только у серого атома
(скорость — по тиру серого, T = 4, P = 32 / дырки — отдельно ничего не делать, `CrossPeriod` уже от тира); два
перекрёстка вплотную по 4 сторонам нельзя (по диагонали можно). Шеврон выхода показывает, куда подключён выход: цвет тира
соседа за выходом.

## Что сделать
1. **`PlaceDecision` (чистый, без Godot) — одно место правила.**
   - `PlaceCellFlags` получает `CrossroadNeighbor` (bool: в одной из 4 соседних клеток стоит перекрёсток; сама клетка не
     считается). Новые причины `PlaceDenyReason`: `CrossroadAdjacent`, `CrossroadNotGray`.
   - `Decide`: если `tool.Crossroad` — тир инструмента не серый → `Deny(CrossroadNotGray)` (защита; рука-перекрёсток
     бывает только серой), `cell.CrossroadNeighbor` → `Deny(CrossroadAdjacent)`. Проверка — после «закрыто/ЧД/звезда/…»,
     **после** проверки `Same`: такой же перекрёсток, уже стоящий рядом с другим (бывает только в старых сохранениях), —
     это `Same` (превью скрыто), а не красный отказ.
   - Новая функция `DecideToggle(in PlaceCellAtom atom, bool crossroadNeighbor)` → `Toggle` / `Deny(причина)`:
     перекрёсток → обычный — всегда можно; обычный → перекрёсток — только серый (`CrossroadNotGray`) и без соседа-
     перекрёстка (`CrossroadAdjacent`). Обломок и замороженные тиры — `Occupied`/`Cargo`, как сейчас.
   - Серый тир — константа 3 (`CoreTier` в CLAUDE.md); заведи именованную константу в `PlaceDecision`, не число в условиях.
2. **`NucleusLayer` вызывает правило.**
   - `EvaluatePlace` заполняет `CrossroadNeighbor` (4 поиска в `_entAt`, `Cross != null`) — превью и клик получают
     отказ из одного места.
   - ЛКМ без инструмента по атому (`ToggleCrossroad`, ~стр. 1909) и клик по такому же атому с инструментом (T039,
     ~стр. 1916) — через `DecideToggle`. `Toggle` → `ToggleCrossroad` (как сейчас); `Deny` → красная вспышка клетки
     (`FlashPlaceDenied`: `CrossroadAdjacent`/`CrossroadNotGray` → `_removeHoldLayer.FlashDenied(row, col, 1)`, как
     `Occupied`) и `_lastPlacedCell`, чтобы удержание не мигало. Клик по такому же цветному атому с инструментом —
     вспышка `CrossroadNotGray` (раньше переключал).
   - `CanBeCrossroad` больше не означает «можно стать перекрёстком» — либо переименуй/сузь, либо оставь как «атом
     пригоден для клика», но решение — только `DecideToggle`.
   - Пипетка (`_handCrossroad`) не меняется: перекрёстки теперь только серые, значит рука-перекрёсток — серая.
3. **Загрузка (`ApplyFieldData`, ~стр. 5432):** `Crossroad = true` у не серого атома — ставится обычным атомом (тот же
   тир, дырки, спин), строка в лог `GD.Print` (сколько таких). Содержимое дырок и сторон в сохранении не хранится
   (CLAUDE.md, T007), поэтому возвращать в инвентарь нечего — ничего не делать. Серые перекрёстки, стоящие вплотную, —
   загружаются как есть (проверки соседства при загрузке нет; они работают по прежним законам). Новые не ставятся рядом
   с ними — правило из шага 1 действует и для них.
4. **Перекрёсток рядом со старыми вплотную стоящими:** `DecideToggle` разрешает «перекрёсток → обычный» всегда, так что
   игрок может развести их. Ничего отдельно не делать.
5. **Шеврон выхода — цвет соседа (только вид).** `NucleusLayer.Crossroads()` отдаёт для каждой из двух сторон выхода тир
   соседа за ней: атом-переносчик Ж/К/С (`IsNormalTier`, не обломок) → его тир; иначе (пусто, серый, звезда, ЧД,
   источник, обломок, закрытая клетка) → «нейтральный». `CrossroadLayer._Draw` красит шеврон: тир → `ChevronTierColors[тир]`,
   нейтральный → цвет из спецификации (новый `[Export]`, по умолчанию — значение из правки художника). Пульс затора — как
   сейчас, поверх цвета. Свой тир перекрёстка (серый) для цвета шеврона больше не используется.
   - Пересчёт при смене соседей — без кеша и событий: `_Draw` уже идёт по видимым перекрёсткам каждый кадр, 2 поиска в
     `_entAt` на перекрёсток. Проверь, что `CrossroadLayer` перерисовывается каждый кадр (иначе — `QueueRedraw` при
     смене атома в соседней клетке: установка, снятие, замена). Ни в хеш, ни в сохранение, ни в `Touch` это не входит.
   - Шевроны входа (`InputChevronColor`) не меняются.
6. Строки в `CLAUDE.md` (разделы T010/T030/T033) и `crossroad-visual-spec.md` — не трогать: CLAUDE.md обновит ведущий
   после слияния, спецификацию — художник.

## Не входит
Значок «в руке перекрёсток», перенос режима при замене, переделка законов перекрёстка (`Crossroad.cs`, `TickCrossroads`),
снос/починка уже стоящих вплотную перекрёстков, подсказки в HUD, новые строки перевода (текста нет).
Прогон `--sim-selfcheck` не нужен: передача частиц не меняется, атомы меняются через тот же `ToggleCrossroad` с `Touch`.

## Критерии готовности
- Сборка без ошибок и предупреждений.
- ЛКМ без инструмента по серому → перекрёсток, повторно → обычный. По Ж/К/С → красная вспышка клетки, режим не меняется.
- Серый перекрёсток стоит; ЛКМ по серому вплотную (N/E/S/W) → красная вспышка, отказ; по диагонали → перекрёсток.
- Пипетка (Q) по перекрёстку → в руке серый перекрёсток; превью над клеткой рядом с другим перекрёстком — красное, клик —
  вспышка, атом не ставится и не заменяется; на клетке без соседа-перекрёстка — ставится.
- Клик по такому же серому с серым инструментом (T039) переключает режим с тем же правилом соседства; по такому же
  цветному — вспышка, без переключения.
- Сохранение с цветным перекрёстком (подготовить вручную: экспорт до слияния или правка JSON `"Crossroad": true` у атома
  `CoreTier` 0) → после импорта атом обычный, в логе строка. Два серых перекрёстка вплотную в JSON → оба загружены
  перекрёстками и работают.
- Шеврон выхода: сосед за выходом Ж → жёлтый тон, К → красный, С → синий; пусто/серый/звезда/ЧД → нейтральный цвет;
  поставили или сняли соседа — шеврон меняет цвет в тот же кадр; затор — красный пульс, как раньше.
- В отчёте — что проверено в игре, что только сборкой.

## Риски
- Низкие. Порядок проверок в `Decide`: не превратить `Same` по уже стоящему перекрёстку в отказ (старые сохранения с
  соседями) — иначе протяжка с перекрёстком в руке будет мигать красным.
- Старые сохранения меняют поведение: цветные перекрёстки исчезают — ожидаемо, это решение GDD.
