# T030 — инструмент в руке: превью на занятой клетке и быстрая замена атома

Модель: Sonnet · effort: medium
Ветка: `feature/tool-replace` от `experimental`.
Зависимости: нет. Передачу частиц и `SimTick` не трогает (замена идёт через те же `RegisterEntity`/`Touch`, что и сейчас) —
`--sim-selfcheck` не гонять. Не запускать параллельно с задачами, правящими ввод ЛКМ/превью в `NucleusLayer`.

## Цель
Решение GDD «Инструмент в руке и быстрая замена» (2026-10-01; https://claude.ai/code/artifact/9cf8f132-726d-4cf1-b623-86551e34a7c4).
Это **не баг**: с выбранным инструментом (в т. ч. пипеткой Q) ЛКМ по занятой клетке молча ничего не делает — так задумано
для перекрёстка (T010: переключение — только **без** инструмента). Меняем правило: инструмент в руке всегда показывает, что
произойдёт в клетке под курсором, и ЛКМ (а также протяжка ЛКМ) заменяет атом, если он отличается.

Правила (атом-переносчик Ж/К/С/серый; инструмент = `_selectedSpawnTier` + число дырок + спин `_currentSpinDirection`):
1. **Превью видно всегда**, в том числе на занятой клетке. Атом в клетке **отличается** (тир, число дырок или спин) —
   превью поверх него, ЛКМ и протяжка заменяют. **Такой же** атом — превью нет, ЛКМ ничего не делает.
   Для атома-перекрёстка спин не сравнивается (у перекрёстка спина нет, `SpinOf` = `NoSpin`) — отличают только тир и дырки.
2. **Нельзя** поставить (звезда или ЧД под курсором, закрытая территория, порт слоя 2 при включённом слое 2, груз-обломок):
   превью **красное**, при клике — красная вспышка, как `DenyIfClosed` для закрытого чанка; для звезды/ЧД — вспышка их следа
   (как отказ в T026, `RemoveHoldLayer.FlashDenied`).
3. **Замена сохраняет режим перекрёстка.** Заменяемый атом-перекрёсток → новый тоже перекрёсток (`Cross` создаётся с новым
   числом дырок, запись в `_crossSet`); обычный → обычный. Содержимое считается как при замене: частицы сгорают,
   атомы-предметы — в инвентарь (настоящий режим); состояние перекрёстка (оси, очереди) не переносится, потому что число
   дырок/тир могут измениться, — режим (и ориентация выходов, если она хранится в атоме, а не в `Crossroad`) сохраняется.
4. **Настоящий режим:** старый атом (Ж/К/С) и атомы-предметы из дырок и с осей — в инвентарь, частицы пропадают
   (`RefundToInventory`, как сейчас), новый тратит атом. Нового нет в инвентаре — превью красное, замены нет, старый остаётся
   (проверка до удаления — уже так в `TryPlaceNucleus`, сохранить).
5. **Сброс инструмента:** Q по пустой клетке (уже есть, `PickNucleusUnderMouse`; проверить, что не сломано) и **повторный клик
   по кнопке панели** с уже выбранным инструментом снимают его. Повторный клик по кнопке той же строки (тот же тир и число
   дырок) = сброс; другая кнопка — смена инструмента, как сейчас. Относится ко всем кнопкам инструментов панели слоя 1
   (атомы, источники, ЧД, звёзды) — единый способ, без особых случаев.
6. **ПКМ не трогать** — только удаление (T026). ЛКМ без инструмента по атому — перекрёсток ↔ обычный (T010) остаётся.

## Что сделать
1. **Чистый класс `PlaceDecision.cs`** (без Godot, `.cs.uid` закоммитить; по образцу `Territory`/`StarSet`). Вход: описание
   инструмента (тир, дырки, спин), описание атома в клетке (нет / тир, дырки, спин, перекрёсток, груз), флаги (клетка открыта,
   занята ЧД/звездой/портом, есть атом в инвентаре). Выход: `Place` (пустая клетка), `Replace`, `Same` (ничего), `Deny` +
   причина (закрыто / ЧД / звезда / порт / груз / нет атома в инвентаре). Одно место истины для превью и для клика —
   `UpdatePlacementPreview` и `TryPlaceNucleus` вызывают его, а не дублируют условия. Дырки атома —
   `HoleCountOf`; тир — `CoreTier`; спин — `Dir` (для `Cross != null` не сравнивать).
2. **Превью**: `Place`/`Replace` — полупрозрачный цвет тира (как сейчас); `Deny` — красное (`DeniedPreviewColor`); `Same` —
   скрыто. Обновляется каждый кадр, на слое 2 — как сейчас (скрыто).
3. **Клик и протяжка**: `TryPlaceNucleus` идёт по решению `PlaceDecision`. `Replace` — удалить старый (`RefundToInventory` +
   `RemoveNucleusEntity`), поставить новый тем же путём, что `Place`, и, если старый был перекрёстком, — новый создать
   перекрёстком (`Cross = new Crossroad(holeCount)`, `_crossSet.Add`, `Touch`). `Deny` — вспышка по причине (чанк/порт/след
   звезды или ЧД/красное превью без вспышки при «нет атома»), без замены. Дедупликация по `_lastPlacedCell` остаётся (протяжка
   по линии не спамит), но **сбрасывается, если в клетку уже вошло изменение** — не нужно: после замены атом в клетке уже
   «такой же», поэтому повторная попытка ничего не сделает.
4. **ЛКМ с инструментом по занятой клетке перестаёт ничего не делать молча:** `Replace`/`Deny` обработаны, `Same` — тихо.
   Ветка `ToggleCrossroad` (без инструмента) не меняется. Груз-обломок (`IsCargo`) — отказ (красная вспышка), как сейчас
   клетка «занята».
5. **Сброс повторным кликом по кнопке панели**: в `SelectSpawnPreset` (и в `SelectTool` звезды/ЧД, `OnEnergyPressed`,
   `OnClusterPressed`) — если выбран ровно этот же инструмент, снять его (`ClearSelection` + `GuiReleaseFocus`), иначе
   выбрать. Кнопки подсвечиваются как сейчас (`ToggleMode`/`ButtonPressed`, если используются — привести в соответствие, чтобы
   кнопка не оставалась нажатой после сброса). Проверить Q по пустой клетке: инструмент снят и кнопка отжата.
6. **Подсказка**: если в подсказке управления (`ControlHints`, T012) или в `en.po` есть строка про ЛКМ/пипетку, поправить
   текст («ЛКМ — поставить или заменить; Q по пустому — снять инструмент»). Новая строка интерфейса — сразу ключ в
   `Data/Localization/en.po`. Логи (`GD.Print`) не переводятся.
7. **`CLAUDE.md`**: короткий пункт «Инструмент в руке и замена (T030)» в «Текущее состояние кода» (класс решения, правила
   замены/режима/режимов инвентаря, сброс) и T030 в список задач; поправить пункт T010, где сказано «ЛКМ по атому … без
   инструмента (`AnyToolSelected`)», если формулировка устарела.

## Не входит
- ПКМ, удаление (T026), перекрёсток-тоггл без инструмента, вид перекрёстка (T029).
- Превью дырок/спина внутри кольца превью (только тир), новые спрайты.
- Замена звёзд/ЧД/источников инструментом (они остаются отказом — красное превью); замена атома звездой и т. п.
- Заморожено: вращатели, бросатели, слой 2, порты (кроме строки отказа «порт»), груз-логика.
- Отмена Ctrl+Z, подтверждение диалогом.

## Критерии готовности
- `dotnet build Singulario.sln` без ошибок и новых предупреждений; логика замены — в классе без Godot.
- Песочница, инструмент К (3 дырки / любые): протяжка ЛКМ по готовой линии Ж заменяет все атомы на К сразу, по одному на
  клетку, без пропусков; превью на занятой клетке видно (цвет К); линия работает после замены (частицы идут).
- Инструмент Ж по готовой линии Ж (те же дырки и спин): превью нет, ничего не меняется; сменить число дырок или спин (R) —
  превью появляется, замена работает.
- Перекрёсток: ЛКМ/протяжка инструментом по перекрёстку заменяет атом, **новый тоже перекрёсток**; по обычному атому —
  обычный. Режим не слетает при смене тира, при смене дырок — тоже.
- Звезда, ЧД, закрытый чанк под инструментом: красное превью, при клике красная вспышка (чанка / следа), ничего не меняется.
- Настоящий режим (M): замена тратит атом нового тира, старый и предметы из дырок — в инвентарь (проверить по HUD);
  нет нового в инвентаре — красное превью, клик ничего не делает, старый атом на месте.
- Сброс: Q по пустой клетке и повторный клик по кнопке панели снимают инструмент, кнопка отжимается; клик по другой кнопке —
  смена инструмента. ЛКМ без инструмента по атому — перекрёсток ↔ обычный, как раньше. ПКМ как раньше.
- `--sim-selfcheck` не нужен. В отчёте — что проверено в игре (по пунктам выше), что нет.

## Риски
- Дубль условий превью и клика разойдётся — поэтому единый `PlaceDecision`.
- Протяжка по большой линии = много замен за кадр: `RebuildChunkMeshes` на каждую — ориентироваться на текущий путь замены
  (он уже такой); если видимо тормозит — отложить пересборку чанка до конца кадра, но без замеров и нагрузочных тестов
  (правило прототипа).
- Спин у перекрёстка хранится как `Dir` старого атома? Если после замены перекрёсток получает `Dir` из `_currentSpinDirection`,
  а `SpinOf` его игнорирует — всё равно проверить, что передача идёт (R над перекрёстком ничего не ломает).
