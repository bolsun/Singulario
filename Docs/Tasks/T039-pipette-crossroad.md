# T039 — пипетка запоминает перекрёсток; клик по такому же атому переключает режим

Модель: Sonnet · effort: medium
Ветка: прямо в `experimental` (малая правка ввода и `PlaceDecision`, симуляция не меняется).
Зависимости: T030, T010, T032 влиты. Не запускать параллельно с задачами, правящими `PlaceDecision.cs`,
`NucleusLayer.TryPlaceNucleus`/`PickNucleusUnderMouse`/`ClearAllTools`.

## Цель
1. Пипетка (Q) по перекрёстку берёт его в руку вместе с тиром, дырками и `OutRot`; установка ставит перекрёсток.
2. Если в руке атом, а в клетке такой же атом (тот же тир, дырки, спин, тот же режим) — клик переключает режим
   перекрёстка у этого атома без инструмента-«ластика» (сейчас ЛКМ-переключение работает только при пустой руке).

Решение пользователя 2026-10-02: **режим решает рука** (замена ставит то, что в руке), никакого наследования режима
от старого атома. Подсказки/значка «в руке перекрёсток» пока нет — только пипетка.

## Что сделать
1. **Рука.** В `NucleusLayer` — поля `_handCrossroad` (bool) и `_handCrossOutRot` (0..3). Пипетка
   (`PickNucleusUnderMouse`) ставит их из атома под курсором (`Cross != null`, `Cross.OutRot`), иначе сбрасывает.
   Кнопки панели (`SelectSpawnPreset` не из пипетки), `ClearAllTools`, смена инструмента на звезду/ЧД/источник —
   сбрасывают оба поля. Проверь, что пипетка зовёт `SelectSpawnPreset` и сброс не затирает только что выставленные поля
   (порядок: сначала выбор пресета, потом поля).
2. **`PlaceDecision`** (чистый, без Godot): `PlaceTool` получает `Crossroad` (bool). «Такой же» (`Same`) — тир, дырки и
   **режим** совпадают (спин сравнивается только если оба не перекрёсток). Разный режим при том же тире/дырках —
   `Replace` (если атом `IsCarrier` и есть что потратить), отказы прежние. Обновить `EvaluatePlace`.
3. **`TryPlaceNucleus`:** режим нового атома — из руки (`_handCrossroad`, `OutRot` из руки), а не из `wasCrossroad`.
   Убрать наследование `wasCrossroad`/`crossOutRot` от старого атома. Новый перекрёсток: `Cross`, `_crossSet`, `Touch`
   (как сейчас).
4. **Клик по такому же атому (`Same`) переключает режим.** В `_UnhandledInput` на ЛКМ (только нажатие, не удержание и
   не протяжка — защита `_lastPlacedCell`, как при установке): если `EvaluatePlace` вернул `Same` и атом — Ж/К/С
   с инструментом в руке, вызвать `ToggleCrossroad(atom)` (содержимое очищается, предметы в инвентарь в настоящем
   режиме — как сейчас). Рука не меняется. Превью для `Same` остаётся скрытым.
5. Строка в `Docs`/`CLAUDE.md` (раздел T030) — обновит ведущий после слияния.

## Не входит
Значок/превью «в руке перекрёсток», горячая клавиша переключения режима в руке, `R` по руке для `OutRot`, серый атом.
Прогон `--sim-selfcheck` не нужен (механика передачи не меняется; ставим атомы через те же `Touch`).

## Критерии готовности
- Сборка без ошибок и предупреждений.
- Q по перекрёстку → ЛКМ по пустой клетке ставит перекрёсток с тем же `OutRot`; Q по обычному атому → обычный.
- Перекрёсток в руке поверх обычного атома того же тира → заменяет его перекрёстком; обычный в руке поверх
  перекрёстка → делает обычным; режим не наследуется.
- Обычный атом в руке, клик по стоящему рядом такому же обычному → он становится перекрёстком; повторный клик → снова
  обычный. Удержание ЛКМ и протяжка через такие клетки режим не мигают.
- Выбор тира на панели и сброс инструмента убирают режим из руки.
- Проверка в игре (ручная): сценарии выше; в отчёте указать, что именно проверено.

## Риски
Низкие: `PlaceDecision` — единое место для превью и клика, расхождения быть не должно; следить, чтобы `Replace` с
равным тиром в настоящем режиме тратил атом и возвращал старый (баланс нуль).
