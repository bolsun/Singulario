# T034 — клетка источника закрыта для установки атомов (кроме песочницы)

Модель: Sonnet · effort: low
Ветка: `feature/deposit-cell-closed` от `experimental`.
Зависимости: T030 влита (`PlaceDecision`). Не запускать параллельно с задачами, правящими `PlaceDecision.cs`,
`EvaluatePlace`/`FlashPlaceDenied` в `NucleusLayer.cs`.

## Цель
GDD «Правила передачи → Добыча с края» (решено 2026-10-02,
https://claude.ai/code/artifact/9cf8f132-726d-4cf1-b623-86551e34a7c4): **клетка источника закрыта для атомов**. Атом добывает
только из соседних источников (N/E/S/W) в дырку, обращённую к источнику, — так код уже работает (`TryCaptureEnergy` смотрит
только на соседние клетки). Задача — запретить игроку ставить атом на клетку источника в настоящем режиме.

## Что сделать
1. **`PlaceDecision.cs`** (чистая логика, без Godot):
   - `PlaceDenyReason.Deposit` — клетка источника (месторождения).
   - В `PlaceCellFlags` — поле `Deposit` (в клетке есть источник любого тира) и `Sandbox`.
   - В `Decide`: `if (cell.Deposit && !cell.Sandbox) return Deny(PlaceDenyReason.Deposit);` — среди проверок клетки, после
     `Port`, до проверок атома. Значит, на источнике отказ и для `Replace`, и для `Same` (красное превью поверх атома из старого
     сохранения — так и задумано: клетка закрыта).
   - Исключение песочницы — здесь, в правиле, а не в `NucleusLayer`.
2. **`NucleusLayer.cs`**:
   - Один помощник `HasSourceAt(int row, int col)` — есть ли источник в клетке атома. Перевод клетки в сетку слоя источников —
     **через центр клетки**, как в `GetRemoveTarget`: `Floor((col + 0.5) * CellSize / layer.CellSize)`. Обход
     `_energyClusterLayers`, `layer.HasClusterAt`.
   - `EvaluatePlace` заполняет `Deposit: HasSourceAt(row, col)`, `Sandbox: Inventory.Sandbox`.
   - `FlashPlaceDenied`: `Deposit` — вспышка клетки `_removeHoldLayer?.FlashDenied(row, col, 1)` (как `Occupied`).
   - Протяжка ЛКМ по линии через месторождение: клетки источника пропускаются с отказом, остальные ставятся — это уже даёт общий
     путь `TryPlaceNucleus` → `EvaluatePlace`, отдельно ничего не делать. Проверь, что протяжка не печатает лог на каждый кадр
     над одной и той же клеткой (если печатает — так же, как у других отказов; новое не вводить).
3. `CLAUDE.md`, раздел T030 (инструмент в руке): одной фразой — «клетка источника — `Deposit`, кроме песочницы (T034)»; в
   список задач — T034.

## Что не входит
- Захват из соседних источников (`TryCaptureEnergy`, период `_energyCaptureTicks`, порядок сторон) — не меняется.
- Старые сохранения и шаблоны с атомами на источниках — грузятся как есть (вопрос в GDD «Обсуждаем»). `PlaceNucleusForImport`,
  `ApplyFieldData`, `PlaceTemplate` не трогать. Атом на источнике по-прежнему снимается ПКМ (T026).
- Установка источника на клетку с атомом, ЧД и звёзды на источниках — без изменений.
- Технологии «Глубинная добыча» и «Скорость добычи» (ранний доступ).
- Новых строк интерфейса нет (`en.po` не трогать). Самопроверку `--sim-selfcheck` не гонять: передача частиц не меняется.

## Критерии готовности
- [ ] Сборка `dotnet build Singulario.sln` без ошибок и новых предупреждений.
- [ ] Настоящий режим (M или новая игра): инструмент-атом над клеткой источника — красное превью; клик — отказ, вспышка клетки,
      атом не тратится из инвентаря.
- [ ] Настоящий режим: атом ставится на соседнюю с источником клетку и добывает в дырку, обращённую к источнику, как раньше.
- [ ] Песочница: на клетку источника атом ставится, как раньше.
- [ ] Протяжка ЛКМ через месторождение в настоящем режиме: атомы встают только на свободные клетки вне источника.
- [ ] Атом на источнике из старого сохранения: загружается, замена инструментом — отказ (красное), ПКМ снимает.
- [ ] Проверено в игре вручную (сказать в отчёте, что именно).

## Риски
- Разная сетка слоя источников и атомов: если перевести клетку не через центр, отказ сдвинется на соседнюю клетку. Брать формулу
  из `GetRemoveTarget`. (`CanPlaceBlackHoleCell` переводит без пересчёта — не трогать, вне задачи.)
- Цена проверки: `HasSourceAt` — словарь на слой, вызывается в превью раз в кадр и при клике; дёшево.
